# 본질 파악 방법론 가이드

이 문서는 이 저장소가 사례를 어떤 순서와 생각으로 정리하는지 처음부터 끝까지 설명한다. 사례 DB를 읽기 전에 한 번 쭉 읽으면, 각 사례에 붙은 칸이 왜 있고 어떻게 읽으면 되는지 알 수 있다.

- 이 문서는 사례를 읽는 법만 다룬다. 제품 기획은 담지 않는다.
- 뼈대는 패스트캠퍼스 강의 '문제 본질 발견의 기술'의 단계(제한없는 가설설정, 의심, 관습과 파괴, 안티오피니언, 트레이드온 → 목표 재분석, 이슈트리, 파레토)다. 여기에 이 DB에서 쓰는 Why not yet, So what, 긍정 오피니언, 대체 왜, 중요 지표 선별을 더해 한 흐름으로 묶었다.
- 예시는 사례 DB의 `dental`(치과 대기)과 `tight-trust`(타이트사주 신뢰)를 쓴다.

---

## 서론: WHAT · WHY · HOW 전략

기획은 **무엇이 문제인가(WHAT) → 왜 그런가(WHY) → 어떻게 풀까(HOW)**의 세 단계이고, 이를 쪼갠 것이 기획의 6단계다. 상황에 따라 일부가 생략·추가될 수 있지만 이 흐름이 정석이다. 결론을 보고할 때도 같은 순서로 말한다(문제에 동의해야 근거를 듣고, 근거에 납득해야 해결을 받아들인다).

| 파트 | 단계 | 이 가이드의 툴 |
|---|---|---|
| WHAT | 1. 문제를 발견한다 | 5 Why, 현상→WHAT, 가설, Why not yet, 관습 파괴→So what, 긍정·안티 오피니언, 트레이드온 |
| | 2. 문제를 구조화한다 | 목표 재분석, 이슈트리 |
| | 3. 우선순위를 정한다 | 파레토, 대체 왜, 중요 지표 |
| WHY | 4. 분석방법을 정하고 분석한다 | PEST, SWOT, 3C 겹침, 앤소프, BCG, (참고) 5F, 아이디어가 먼저일 때: 설문·수치 대입·컨슈머 저니 |
| | 5. 발견한 내용을 통합한다 | 결론 하나를 근거 서너 개가 받치는 한 장, 근거끼리 교차 확인(SO↔3C 진입, PEST↔타이밍, So what↔목표, 의도↔지표) |
| HOW | 6. 솔루션을 제안한다 | 다섯 원칙: 믿지 마라 · 누수 확인 · 해답의 수 · 자기부정 · 후속 액션 (9장) |

## 0. 목표: 본질 파악

사례를 모으는 이유는 "무엇이 통했나"를 외우기 위해서가 아니다. 겉으로 보이는 현상 아래에서 **진짜 문제가 무엇이었고, 그것이 왜 풀렸는지**를 보기 위해서다.

본질은 두 힘을 함께 쓸 때 보인다.

- **가설을 세우는 힘:** 가능한 답을 제한 없이 많이 꺼낸다.
- **가설을 부수는 힘:** 꺼낸 답을 의심하고, 관습을 깨고, 반대 목소리를 듣고, 양자택일을 거부하며 깎아 낸다.

처음 세운 가설이 이 과정에서 크게 뒤틀리거나 버려지는 것은 실패가 아니라 좋은 신호다. 가설이 본질에 가까워지고 있다는 뜻이기 때문이다.

**분석 툴은 왜 쓰나.** PEST·SWOT·3C·앤소프·BCG 같은 툴을 쓰면 말로 설명하기 어려운 비즈니스도 몇 칸짜리 틀에 넣어 간략하게 구조화해 볼 수 있다. 칸이 정해져 있으니 빠진 곳이 보이고, 다른 회사와 같은 틀로 나란히 비교할 수 있다.

## 1. 전체 흐름 한눈에

| 묶음 | 단계 | 묻는 것 | DB 칸 |
|---|---|---|---|
| 문제 깨닫기 | 분석 A. 5 Why (과정) | 증상에서 "왜?"를 거듭해 근본 원인까지 | `five_why` |
| | 현상 → WHAT | 근본 원인을 문제로 정의하면? | `what` |
| | 분석 B. PEST | 정치·법(P)과 기술(T) 중 무엇이 결정적이었나 (경제·사회는 참고) | `pest` |
| | 분석 C. SWOT(SO·WO·ST) | 강점으로 잡을 기회, 기회로 옮겨 가려고 메울 약점, 강점으로 막을 위협 | `swot` |
| | 분석 D. 3C | 세 원을 겹친 A~H 8칸 중 우리 상황에 맞는 시장(진입 칸)은? | `three_c` (overlap·entry) |
| | 분석 E. 앤소프 | 시장×제품으로 어느 방향으로 넓히나 | `ansoff` |
| | 분석 F. BCG (제품이 여러 개일 때) | 어느 물음표를 스타로 키우고, 돈줄은 무엇인가 | `bcg` |
| | 1. 제한없는 가설설정 | 가능한 답을 모두 꺼내면? | `hyps` |
| 본질 찾기 | 2. 의심 = Why not yet | 왜 지금까지 아무도 안 했나 | `hyps[].why_not_yet`, `barrier` |
| | 3. 관습과 파괴 (과정) | 그 관습을 깨면 무엇이 열리나 ("그래서?" 반복) | `so_what.steps` |
| | So what (결론) | 그래서 결론은 한 문장으로 무엇인가 | `so_what.conclusion` |
| | 4. 긍정 오피니언 | 핵심 고객은 왜 좋아하나 | `pro_opinion` |
| | 5. 안티오피니언 | 안 쓰는 사람·떠난 사람·비판자는 뭐라 하나 | `anti_opinion` |
| | 6. 트레이드온 | 둘 중 하나라던 것을 어떻게 둘 다 잡았나 | `trade_on` |
| 구조화 | 7. 목표 재분석 | 처음 목표를 본질에 맞게 다시 쓰면? | `goal` |
| | 8. 이슈트리 | 재정의한 목표를 빠짐없이 겹치지 않게 쪼개면? | `issue_tree` |
| | 9. 파레토 | 속도×임팩트로 볼 때 중요한 소수는? | `pareto` |
| | 10. 대체 왜 | 이 목표를 대체 왜 원하나, 진짜 의도는? | `deep_why` |
| | 11. 중요 지표 선별 | 무엇을 재고 무엇을 쫓지 않을까, 어떻게 골랐나 | `key_metrics` |
| 결과 | 해결 | 그 사례가 실제로 한 것 | `solution` |

모든 사례에는 1~3과 6이 있다. 핵심 사례(deep 90건)에는 5 Why, PEST, SWOT(SO·WO·ST), 3C, So what 결론, 4·5와 7~11까지 모두 있다.

**과정과 결론을 나눈다.** 5 Why와 관습 파괴는 생각을 파고드는 **과정**이고, So what은 그 과정 끝에 내리는 **결론** 한 문장이다. 과정만 길게 쓰고 결론을 안 내리면 "그래서 뭘 하라는 건데?"가 남는다. 결론만 쓰고 과정이 없으면 왜 그 결론인지 검증할 수 없다.

## 2. 문제 깨닫기

### 분석 A. 5 Why: 근본 원인까지 파고드는 과정

증상에서 출발해 "왜?"를 3~5번 거듭 묻는다. 한 번 묻고 멈추면 겉 원인에서 해결을 찾게 된다. 원래 도요타 생산 현장에서 쓰던 방법이다.

> 치과
> - 왜 대기실 불만이 많나? 기다리는 게 괴롭다.
> - 왜 괴로운가? 얼마나 더 기다려야 할지 모른다.
> - 왜 모르나? 진료 진행 상황을 환자에게 알려 주는 장치가 없다.
> - 근본 원인: 대기 시간이 환자에게 보이지 않는다.

5 Why는 **과정**이다. 여기서 바로 해결로 뛰지 않고, 근본 원인을 WHAT으로 정의한 뒤 가설과 의심을 거쳐 마지막에 So what으로 결론을 내린다.

**주의:** "왜?"의 답이 사람 탓("직원이 실수해서")에서 멈추면 안 된다. 그 실수가 왜 가능했는지, 구조나 장치까지 내려간다.

### 현상 → WHAT

사람들은 보통 증상에서 바로 해결로 간다. "대기실 불만이 많다 → 대기실을 넓히자." 이렇게 가면 뻔한 답이 나온다.

먼저 세 가지를 나눠 적는다.

- **상황:** 무슨 일이 벌어지고 있나.
- **증상:** 겉으로 보이는 불만이나 수치.
- **문제(WHAT):** 그 증상을 만드는 진짜 원인.

> 치과: 증상은 "대기실 불만이 많다". 문제는 "환자들이 기다리는 시간을 지루하고 불안하게 느낀다", 즉 공간의 질이 아니라 시간의 질이다.

### 분석 B. PEST: 외부 환경 보기 (P·T 중심)

문제를 둘러싼 바깥 환경을 네 가지로 나눠 보되, **정치·법(P)과 기술(T)을 위주로 본다.** 새 사업의 판을 실제로 바꾸는 것은 대개 규제의 변화와 기술의 변화이기 때문이다. 경제(E)와 사회(S)는 늘 어느 정도 작동하고 막연해지기 쉬워 참고로만 적고, 결정 근거로 쓰지 않는다.

| 요인 | 보는 것 | 예 |
|---|---|---|
| P 정치·법 | 규제, 법 개정, 정책 | 개정 전자상거래법(2025)의 다크패턴 금지, 청소년 AI 보호 법안 |
| E 경제 | 비용, 가격, 경기, 시장 규모 | 인큐베이터 가격과 낮은 소득, 광고 단가 |
| S 사회·문화 | 습관, 가치관, 인구 변화 | 맞벌이로 하교 마중이 어려움, MZ 사주 놀이 문화 |
| T 기술 | 새 기술, 보급, 원가 하락 | 스마트폰 세로 스크롤, 생성형 AI |

PEST는 Why not yet의 **타이밍** 장벽과 이어진다. "왜 지금 되나?"의 답은 대개 PEST 중 하나가 바뀐 것이다. 예를 들어 웹툰은 스마트폰(T)이, 엠페사는 비은행 금융을 허용한 규제 공백(P)과 휴대폰 보급(T)이 결정적이었다.

치과 사례에서 P·T 중 결정적인 것은 기술(대기 알림 도구 보급)이다. 사회 요인(기다림을 손해로 느끼는 문화)은 참고로만 둔다. DB에서는 P·T 핵심만 따로 뽑아 보여 주고, P·T가 모두 약한 사례는 'P·T 영향 적음'으로 표시한다.

### 분석 C. SWOT: 세 칸만 쓴다 (WT 제외)

SWOT 4분면을 다 채우는 것은 요즘 실무에서 큰 의미가 없다. 대신 강점을 쓰는 두 칸과, 기회로 옮겨 가는 한 칸만 쓴다.

| 칸 | 묻는 것 | 치과 예 |
|---|---|---|
| SO (강점 → 기회) | 우리 강점으로 어떤 기회를 잡을 수 있나 | 신뢰받는 의료진(강점)이 대기 알림 도구 보급(기회)을 타고 진료 단계와 남은 시간을 직접 안내 |
| WO (약점 → 기회) | 그 기회로 옮겨 가려면 어떤 약점을 메워야 하나 | 대기 정보가 안 보이는 약점을 알림·진행 표시로 메워 기회로 이동 |
| ST (강점 → 위협) | 우리 강점으로 어떤 위협을 막을 수 있나 | 근처 경쟁 치과의 쾌적한 시설(위협)을 의료진 신뢰와 진행 안내로 피함 |

**WT(약점이면서 기회도 없는 칸)는 쓰지 않는다.** 약점과 위협이 겹친 곳은 피할 목록일 뿐 움직일 방향을 주지 않기 때문이다.

### 분석 D. 3C: 빈자리 찾기

고객(Customer), 경쟁(Competitor), 자사(Company)를 나란히 놓고 세 원이 만드는 **빈자리**를 찾는다. 빈자리는 고객이 원하는데 경쟁은 못 채우고, 자사는 채울 수 있는 곳이다.

| 칸 | 묻는 것 | 치과 예 |
|---|---|---|
| 고객 | 누가 무엇을 원하나 | 언제 끝날지 알고 싶은 환자 |
| 경쟁 | 경쟁자는 무엇을 하고 무엇을 못 하나 | 인테리어·시설 경쟁만 한다 |
| 자사 | 우리는 무엇을 할 수 있나 | 진료 흐름을 아는 의료진 |
| 빈자리 | 세 칸이 만드는 기회 | 대기 시간을 보여 주는 안내 |

3C의 빈자리는 SWOT의 SO(강점으로 잡을 기회)와 같은 곳을 다른 각도에서 확인하는 일이다. 둘이 다르게 나오면 어느 한쪽 분석이 틀렸다는 신호다. 경쟁 칸에는 같은 업종만이 아니라 고객이 대신 쓰는 것도 넣는다. 밀크셰이크의 경쟁자는 다른 셰이크가 아니라 베이글과 바나나였다.

#### 3C는 따로 쓰지 않고 겹쳐 쓴다: A~H 8칸

3C의 목적은 **우리 상황에 맞는 시장을 찾는 것**이다. 고객·경쟁·자사를 각각 적고 끝내면 의미가 없다. 세 원을 겹치면 8칸이 생기고, 이 8칸이 시장 전체를 빠짐없이 겹침 없이(MECE) 나눈다.

| 칸 | 겹침 | 뜻 | 보통의 판단 |
|---|---|---|---|
| A | 고객만 | 고객 니즈는 있는데 아직 아무도 들어가지 않은 영역 | 새로 들어갈 기회 (→ [Section A 디깅](3c-section-a.md)) |
| B | 고객∩경쟁 | 경쟁만 채우는 니즈(우리 열세) | 메울지, 피할지 결정 |
| C | 고객∩자사 | 우리만 채우는 니즈(차별) | 가장 먼저 지킬 자리 |
| D | 셋 다 | 모두가 채우는 기본기 | 빠지면 탈락, 여기서 이기기는 어렵다 |
| E | 경쟁∩자사 | 현재 고객은 없지만 경쟁사와 우리가 싸우는 영역 | 줄일 소모전 |
| F | 경쟁만 | 경쟁사 혼자 하는, 고객 무관한 것 | 따라 하지 않는다 |
| G | 자사만 | 우리 혼자 하는, 고객 무관한 것 | 자기만족, 정리 대상 |
| H | 밖 | 아무도 아직 발견하지 못해 언제 G·A·F가 될지 알 수 없는 영역 | 미래·잠재, 검증 필요 |

규칙은 세 가지다. ① A~H로 전 영역을 덮는다. ② 우리 회사·제품의 정확한 위치를 안다. ③ 그중 우리가 **어디에 진입할지** 고른다. 진입 칸은 고객이 있는 A·B·C·D·H에서만 고른다(E·F·G는 고객이 없다). 대부분은 C를 지키거나 A로 들어가고, B는 열세를 메울 가치가 있을 때만 고른다.

치과 예: A 남은 대기 시간 알기 / B 대형 병원의 넓은 대기실 / C 진료 흐름 기반 대기 안내 / D 정확한 진료 / E 인테리어 경쟁 / F 고급 소품 / G 의료진 학력 자랑 / H 대기 중 건강 교육 → **진입 A·C**: 아무도 안 주는 대기 정보를 진료 흐름 지식으로 채운다.

실패 사례도 이 칸으로 보면 원인이 선명해진다. 주서로는 고객이 없는 G(자사만)에 서 있었고, 노키아·야후는 경쟁만 채운 B(앱 생태계·검색)를 끝내 메우지 못했다. DB에서는 `three_c.overlap`(A~H), `three_c.entry`(진입 칸), `three_c.entry_why`(이유)에 있다.

### 참고: 5F(파이브 포스) — 개념만, DB에는 넣지 않는다

마이클 포터의 5F는 한 산업의 경쟁 압력을 다섯 가지로 나눠 보는 툴이다. 우리 고객사(클라이언트)를 둘러싼 위협을 파악하는 용도다.

| 힘 | 묻는 것 |
|---|---|
| 기존 경쟁자 | 같은 시장 안에서 경쟁이 얼마나 치열한가 |
| 새로운 시장진입자 | 새로 들어오기 쉬운 시장인가 |
| 대체 제품·대체 서비스 | 다른 방법으로 같은 문제를 풀 수 있나 |
| 고객 | 고객이 가격·조건을 좌우할 힘이 큰가 |
| 공급자 | 공급자가 가격·조건을 좌우할 힘이 큰가 |

**현대에 맞지 않는 이유.** 공급자를 경쟁자처럼 '힘을 겨루는 상대'로 규정한다. 지금은 공급자가 플랫폼의 파트너이자 함께 가치를 만드는 쪽인 경우가 많다(앱스토어 개발자, 배달 앱의 가게, 캐릭터챗 창작자). 실제 현장에서도 잘 쓰지 않으니 개념만 알아 둔다.

**대신 이 DB에서는 이렇게 본다.**

- 기존 경쟁자·대체재·새 진입자 → **3C 겹침의 경쟁 원**(B·D·E·F). 경쟁 칸에는 같은 업종만이 아니라 대체재까지 넣는다(밀크셰이크의 경쟁자는 바나나).
- 위협 전반 → **SWOT의 ST**(강점으로 위협을 막는다).
- 공급자 → 경쟁자가 아니라 **지켜야 할 파트너**로 보고, 공급자 쪽 **안티 오피니언**으로 확인한다. DB의 실패 사례 상당수가 공급자를 상대로만 봐서 무너졌다: 그루폰(가게가 손해), 바인(창작자 보상 없음), 인스타카트(쇼퍼 수입 감소), 크랙은 반대로 창작자에게 현금을 줘 독점 콘텐츠를 모았다.

### 앤소프 매트릭스: 시장 × 제품으로 확장 방향 고르기

신제품·신사업으로 넓힐 때 쓰는 툴이다. 시장(기존·신)과 제품(기존·신)을 2×2로 놓는다. 3C 겹침의 A~H 칸과 헷갈리지 않게 여기서는 글자 대신 이름으로 부른다.

| | 기존 제품 | 신제품 |
|---|---|---|
| **신시장** | 시장개척: 기존 제품으로 새 시장을 연다 | 다각화: 신제품으로 신시장에 들어간다(성공률이 가장 낮다) |
| **기존 시장** | 시장침투: 기존 제품으로 기존 시장에 더 깊이 들어간다 | 신제품개발: 신제품으로 기존 시장을 공략한다 |

**집중 전략은 신제품개발과 시장개척 두 칸이다.** 둘 다 하나는 이미 아는 것(시장 또는 제품)을 쥐고, 하나만 새로 한다. 그래서 성장 폭은 있고 위험은 감당할 만하다.

- 시장침투: 기본기. 성장 폭이 작아 확장 전략의 중심은 아니다.
- 신제품개발(집중): 이미 믿어 주는 기존 고객에게 새 제품을 낸다.
- 시장개척(집중): 이미 검증된 제품을 새 고객에게 가져간다.
- 다각화(최종 목표): 시장과 제품을 둘 다 새로 해서 성공률이 가장 낮다. 그래도 결국 도달해야 할 목표다. 한 시장·한 제품에 머문 회사는 그 시장이 꺾일 때 함께 꺾이기 때문이다(코닥·노키아·블록버스터).

새로운 것이 하나 늘 때마다 모르는 것이 늘어 성공률이 떨어진다. 집중 전략 두 칸은 '새것 하나'만 감당하는 자리다.

**다각화는 목표, 집중 전략은 거기로 가는 다리다.** 맨손으로 바로 다각화에 뛰어들면 실패하기 쉽다. 신제품개발로 새 제품을 만드는 역량을, 시장개척으로 새 고객을 상대하는 역량을 하나씩 쌓으면, 다각화는 '둘 다 새것'이 아니라 '이미 해 본 두 가지를 합치는 일'이 된다.

| 단계 | 앤소프 칸 | 쌓는 것 |
|---|---|---|
| 1. 기본기 | 시장침투 | 지금 고객·제품에서의 C(우리만 채우는 자리) |
| 2. 집중 | 신제품개발 | 새 제품을 만들어 내는 역량 |
| 2. 집중 | 시장개척 | 새 고객을 상대하는 역량 |
| 3. 목표 | 다각화 | 1~2에서 쌓은 역량을 합쳐 새 시장·새 제품으로 |

DB의 다각화 성공 사례가 이 경로다. 아마존은 커머스(침투)와 마켓플레이스·프라임(신제품개발)으로 인프라 역량을 쌓은 뒤 AWS로 갔다. 애플은 맥(기존)에서 아이팟·아이튠즈로 소비자 기기와 콘텐츠 유통을 익힌 뒤 아이폰으로 갔다. 반대로 레고는 핵심 브릭이 흔들린 상태에서 테마파크·의류로 다각화했다가 위기를 맞았고, 핵심으로 돌아온 뒤 다시 영화·게임으로 넓혔다.

**3C 겹침과 잇기.** 3C로 C(우리만 채우는 자리)를 만든 뒤 넓히는 길이 곧 앤소프의 네 칸이다.

| 3C에서의 움직임 | 앤소프 칸 | DB 사례 |
|---|---|---|
| C를 지키고 더 깊게, 경쟁 B를 뺏기 | 시장침투 | 쿠팡 로켓와우, 아마존 프라임, 코스트코 회원제 |
| 같은 고객의 옆 니즈(인접 A) | 신제품개발 | 카카오톡 이모티콘, 고젝 배달, 크랙 기억 기능 |
| 같은 역량을 새 고객에게(H→A) | 시장개척 | 크랙 북미(OOC), 네이버웹툰 글로벌, 비비고 만두 |
| 새 고객·새 제품 동시에 | 다각화 | 성공: 아마존→AWS(내부 역량이 있었다) / 실패: 레고 위기 때 테마파크·의류 확장 |

DB에서는 사례마다 해결책이 네 칸 중 어디인지 `ansoff`(`db/meta/ansoff.txt`)에 적고, 신제품개발·시장개척이면 `ansoff.focus`(집중 전략)가 참이다. 기준은 해결 전에 그 회사가 팔던 제품과 상대하던 고객이고, 스타트업이면 그 업계의 기존 제품·고객이다.

다각화가 성공한 경우에도 맨손이 아니었다. AWS는 아마존이 이미 내부에서 쓰던 인프라 역량을 밖으로 판 것이다. 역량 없이 둘 다 새로 하는 것이 위험하다.

### BCG 매트릭스: 제품이 여러 개일 때 포트폴리오 정리

보스턴 컨설팅 그룹(BCG)이 만든 툴이다. **회사에 제품·사업이 여러 개일 때** 각각을 시장성장률(세로)과 시장점유율(가로)로 놓고, 어디에 돈과 사람을 넣을지 정한다. 제품이 하나뿐인 회사에는 쓰지 않는다.

| | 점유율 낮음 | 점유율 높음 |
|---|---|---|
| **성장 빠름** | 물음표(Question Mark, 유망주): 점유는 낮지만 시장이 빨리 큰다 | 스타(Star): 점유도 높고 시장도 빨리 큰다 |
| **성장 느림** | 개(Dog, 사양사업): 점유도 낮고 시장도 느리다 | 캐시카우(Cash Cow): 시장은 느리지만 점유가 높다 |

**보통은 물음표를 스타로 키울 때 쓴다.** 성장하는 시장에서 아직 점유가 낮은 유망주 가운데 무엇을 골라 키울지가 핵심 질문이다. 나머지 칸은 그 판단을 돕는다.

- 캐시카우: 돈줄. 더 키우기보다 현금을 거둬 물음표를 키우는 데 쓴다.
- 물음표: 골라서 투자한다. 다 키울 수 없으니 스타가 될 것만 남기고 나머지는 접는다.
- 스타: 점유를 지키며 계속 투자한다. 시장 성장이 느려지면 캐시카우가 된다.
- 개: 정리 후보다. 다만 **확답하지 않는다**(아래).

정석 흐름은 **캐시카우의 현금 → 물음표 육성 → 스타 → (시장이 성숙하면) 캐시카우**다. 넷플릭스는 DVD 우편 대여(캐시카우) 현금으로 스트리밍(물음표)을 키워 스타로 만들고 DVD를 접었다. 아마존은 커머스(캐시카우) 역량과 현금으로 AWS(물음표)를 스타로 키웠다.

**캐시카우의 돈으로 물음표를 키우는 이유: 유망주는 키워 봐야 안다.** 어떤 물음표가 스타가 될지는 미리 알 수 없다. 그래서 캐시카우가 버는 현금으로 물음표 몇 개에 나눠 투자하고, 키워 보면서 반응이 오는 것에 더 싣는다. 캐시카우 → 물음표 → 스타로 이어지는 화살표가 이 툴의 기본 동작이다.

**개(사양사업)에 대해서는 확답하지 않는다.** '저성장·저점유'는 지금 시점의 판정일 뿐이다. 트렌드는 언제 어떻게 돌아올지 모른다. 필름 카메라·LP 레코드는 다시 유행했고, 크록스는 '못생긴 신발'에서 개성 표현 도구로 되살아났으며, 비아그라는 실패한 협심증 후보 물질에서 나왔다. 그래서 개는 바로 버리지 말고 ① 비용을 줄여 최소한으로 유지하며 지켜보거나 ② 다른 시장으로 다시 정의해 보거나 ③ 정말 가망이 없을 때 정리한다. 개를 정리할 때도 그 역량·자산(브랜드, 기술, 고객 데이터)은 남겨 둔다. DB에 '철수'로 적힌 것도 그 시점의 결정이지 영원한 결론은 아니다.

**반대로 '될 것 같은 것'도 확답하지 않는다.** 물음표를 스타로 키울 후보로 고르는 것은 미래에 대한 판단이다. 지금 잘 커 보이는 사업도 시장이 꺾이거나 규제·기술이 바뀌면 멈춘다(위워크, 클럽하우스). 그래서 후보는 '될 것'이 아니라 '키워 볼 만한 것'으로 적고, 무엇이 보이면 더 싣고 무엇이 보이면 접을지 기준을 함께 정한다. DB의 전 → 후 칸은 지나고 나서 본 결과이고, 아직 진행 중인 사업(크랙 해외, 네이버 캐릭터챗 등)은 물음표로 남겨 둔다.

실패도 같은 칸으로 읽힌다. 코닥과 블록버스터는 캐시카우를 지키느라 물음표(디지털카메라, 온라인 대여)에 투자하지 않아 둘 다 잃었다. 반대로 애플(1997)은 개가 된 제품 대부분을 철수하고 네 제품에 집중해 살아났다.

**앤소프·3C와 잇기.** 물음표는 대개 앤소프의 신제품개발·시장개척(집중 전략)이나 다각화에서 나온다. 3C로 고른 진입 칸(A·C)이 그 물음표가 노리는 시장이고, BCG는 그 물음표에 캐시카우의 돈을 얼마나 넣을지 정하는 단계다.

**주의.** 시장을 넓게 잡을지 좁게 잡을지에 따라 칸이 바뀐다. 점유율은 1위 대비 상대 점유율로 보고, 시장 정의를 함께 적는다. 또 캐시카우를 '돈만 뽑는 곳'으로 방치하면 코닥처럼 함께 무너진다.

DB에서는 제품이 여러 개인 회사의 사례 62건에만 `bcg`(`db/meta/bcg.txt`)를 적는다: 해결 당시의 포트폴리오(사업별 칸), 이 사례가 다룬 사업, 전 → 후 칸, 이유. 물음표 → 스타면 `bcg.q_to_star`가 참이고(44건), 돈줄이 된 캐시카우는 `bcg.funders`에 있다. 단일 제품 사례는 `bcg`가 비어 있다.

### 1. 제한없는 가설설정

이 단계에서는 판단을 미룬다. 좋은지 나쁜지 따지지 않고 가능한 답을 최대한 많이 적는다. 관점을 바꿔 가며 적으면 빠진 곳이 줄어든다.

| 관점 | 묻는 것 |
|---|---|
| 고객 | 고객이 진짜 힘들어하는 것은? |
| 시점 | 언제 그 문제가 생기나, 무엇이 최근에 바뀌었나? |
| 가격 | 돈을 내는 방식을 바꾸면? |
| 채널 | 닿는 경로를 바꾸면? |
| 경쟁 | 경쟁자는 누구이고 무엇을 안 하나? |
| 제약 | 무엇이 막고 있나, 그 제약은 진짜인가? |
| 통념 | 모두가 당연하게 여기는 것은? |

핵심 사례는 관점을 3개 이상 쓰도록 검사기가 확인한다.

> 치과 가설: ① 대기실을 넓히고 꾸민다(제약) ② 의사를 늘려 대기를 없앤다(제약) ③ 환자는 기다리는 시간의 불확실성 때문에 힘들다(고객) ④ 예상 대기 시간을 휴대폰으로 알린다(채널)

## 3. 본질 찾기: 가설을 부수는 힘

### 2. 의심 = Why not yet

강의의 '의심'은 특히 **클라이언트가 들고 온 가설을 의심하라**는 뜻이다. 이 DB에서는 모든 가설에 "그렇게 좋은 생각이면 왜 지금까지 아무도 안 했나?"를 묻는다. 답은 네 가지로 갈린다.

| 판정 | 뜻 | 결과 | 장벽 예 |
|---|---|---|---|
| 뻔함 | 이미 다들 하는데 안 풀렸다 | 탈락 | 이미 경쟁 중, 본질이 아님 |
| 불가능 | 비용·규제·기술 때문에 지금은 못 한다 | 탈락 | 비용, 규제, 기술, 구조, 사회적 수용 |
| 통념의 맹점 | 다들 당연하게 여겨서 안 봤다 | **생존** | 통념, 기존 강자의 이해관계, 문제·고객 정의 |
| 타이밍 | 조건이 최근에 바뀌어 이제 된다 | **생존** | 기술·규제·행동·시장 변화, 외부 충격 |

> 치과: ① 대기실 넓히기는 '뻔함'(이미 많이 했는데 불만이 남았다). ② 의사 늘리기는 '불가능'(비용). ③ 시간의 불확실성은 '통념의 맹점'(업계가 대기를 공간 문제로만 정의했다). → 생존.

클라이언트가 처음 들고 온 답이 대개 첫 번째 가설이고, 이 단계에서 '뻔함'으로 걸러진다.

### 3. 관습과 파괴 (과정) → So what (결론)

Why not yet이 "어떤 관습이 막고 있었나"를 찾았다면, 관습 파괴 과정은 **"그 관습을 깨면 무엇이 열리나"**를 "그래서?"로 2~3번 거듭 묻는다. 그 끝에 **So what 결론**을 한 문장으로 내린다.

> 치과
> - 의심: 업계가 대기를 공간 문제로만 정의했다.
> - 그래서? 시간은 아무도 손대지 않은 빈자리다.
> - 그래서? 시간이 괴로운 이유는 언제 끝날지 모르고 할 일이 없어서다.
> - 그래서? 끝을 예측하게 하고 쓸모를 주면 같은 시간도 짧게 느낀다.
> - **So what (결론): 기다림을 줄이지 말고 보이게 하라.**
> - 해결: 예상 대기 시간 안내와 진료 과정 설명 콘텐츠.

생존 가설이 '통념의 맹점'이면 관습 파괴형, '타이밍'이면 조건 변화형("바뀐 조건이 무엇을 가능하게 하나")으로 표시된다.

### 4. 긍정 오피니언

핵심 고객(많이 쓰고 돈 내는 사람)이 **왜 좋아하는지** 듣는다. 좋아하는 이유가 곧 지켜야 할 본질이다.

### 5. 안티오피니언

안 쓰는 사람, 떠난 사람, 비판하는 사람의 말을 꼼꼼히 듣는다. 불편한 말 속에 가설이 놓친 것이 있다.

> 타이트사주: 안티는 "만세력이 처음부터 틀리고 일간부터 다르다"(Blind 글). 드러난 본질은 "고객은 해석보다 계산을 먼저 검증한다".

**주의:** 오피니언은 실제 목소리여야 의미가 있다. DB에서 출처 URL이 붙은 것만 실제 발언이고, '추정'은 사례 내용에서 도출한 해석이다.

### 6. 트레이드온

업계가 "둘 중 하나"라고 여긴 트레이드오프(A 대 B)를 깨고 **둘 다 잡는 방법**을 찾는다.

> 치과: '대기 시간 단축 대 비용' → 시간을 줄이지 않고 체감 시간을 바꿔, 비용 없이 불만을 줄였다.
> 치폴레: '빠름 대 좋은 재료' → 재료를 미리 준비하고 눈앞에서 조립해 둘 다 잡았다.

실패 사례는 왜 둘 다 못 잡았는지를 적는다.

## 4. 구조화: 찾은 문제를 정리하고 줄이기

### 7. 목표 재분석

처음 세운 목표(표면 목표)를 본질에 맞게 다시 쓰고, 성공을 잴 지표를 정한다.

> 치과: '대기실을 넓고 쾌적하게' → '기다리는 시간을 예측 가능하고 쓸모 있게'. 지표는 대기 관련 불만 건수.

### 8. 이슈트리

재정의한 목표를 질문(루트)으로 두고 **빠짐없이, 겹치지 않게(MECE)** 쪼갠다. 이 DB에서는 3갈래 × 하위 이슈 2개로 쪼개고, 그 사례가 실제로 공략한 갈래 하나를 표시한다.

> 치과: 대기 불만을 어떻게 줄일까
> - 공간: 넓이, 인테리어
> - **시간의 불확실성: 남은 시간 모름, 진행 단계 모름 ← 공략**
> - 할 일 없음: 볼거리 부족, 정보 부족
> - 고른 이유: 공간은 이미 많이 바꿨는데 불만이 남아 원인이 시간에 있었다.

### 9. 파레토 = 속도 × 임팩트로 중요한 소수 고르기

결과의 대부분은 소수의 원인이 만든다(20:80). 이슈트리의 하위 이슈를 전부 하지 말고, **속도**(빨리·싸게 할 수 있나)와 **임팩트**(목표 지표를 얼마나 움직이나)로 매겨 소수만 고른다.

| 사분면 | 조건 | 다루는 법 |
|---|---|---|
| 퀵윈 | 속도 4 이상 · 임팩트 4 이상 | 바로 한다 |
| 큰 베팅 | 속도 3 이하 · 임팩트 4 이상 | 골라서 투자한다 |
| 잡일 | 속도 4 이상 · 임팩트 3 이하 | 여유 있을 때만 |
| 보류 | 나머지 | 하지 않는다 |

임팩트 4 미만은 고르지 않는다.

> 치과: '남은 시간 모름'(속도 5·임팩트 5)과 '진행 단계 모름'(4·4)이 퀵윈. 넓이(1·2)와 인테리어(2·2)는 보류.
> 타이트사주: 만세력 보정(3·5)은 큰 베팅, 환불 경로 노출(5·4)은 퀵윈.

### 10. 대체 왜: 진짜 의도 찾기

파레토로 고른 뒤에 한 번 더 의심한다. **"이 목표를 대체 왜 원하나?"** 목표를 세운 사람이 말한 목적 뒤에는 대개 사업 의도가 있다. 예를 들어 고객 만족도가 목적이라고 하지만, 실은 만족도를 올려 매출을 올리고 싶은 경우가 많다.

의도는 일곱 가지로 나눈다: 매출, 이익·원가, 유지·재구매, 신규 성장, 법적·규제 위험, 브랜드 신뢰, 공익·사명.

> 치과
> - 대기 불만을 왜 줄이나? 불만이 쌓이면 환자가 떠난다.
> - 떠나면 왜 문제인가? 치과 매출은 재방문과 소개에서 나온다.
> - 진짜 의도(유지·재구매): 재방문·소개 환자를 지켜 매출을 유지한다. 의도 지표는 재방문율·소개 환자 수.

진짜 의도를 알면 "불만만 줄이고 재방문은 그대로"인 해결을 피할 수 있다.

**의도의 방향: 올리기 대 지키기.** 진짜 의도를 찾았다고 늘 그 지표를 올려야 하는 것은 아니다. 두 가지로 나눈다.

| 방향 | 성공 기준 | 예 |
|---|---|---|
| 올리기 (`raise`) | 의도 지표가 지금보다 올라야 성공 | 출근길 밀크셰이크: 아침 시간대 매출을 올린다 |
| 지키기 (`hold`) | 의도 지표가 낮아지지만 않으면 성공 (올리지 않아도 됨) | 매출은 건드리지 않고 고객 만족도만 높인다 |

지키기는 생각보다 많다. 치과는 환자 경험을 높이되 재방문·소개가 줄지만 않으면 된다. 크랙은 청소년 상한을 두되 성인 이용과 전체 매출이 줄지 않으면 된다. 다크패턴 규제 대응은 긴급성 장치를 빼되 결제 매출이 크게 줄지 않으면 된다. 지키기에서 의도 지표는 사실상 **가드레일**처럼 작동한다. 그래서 "어디까지 내려가면 안 되는가"라는 기준을 함께 적는다.

방향을 먼저 정하면 해결책의 범위가 달라진다. 올리기라면 매출을 키우는 공격적인 안까지 본다. 지키기라면 매출에 손대지 않는 안만 고르고, 남는 힘을 목표 지표(만족도 등)에 쓴다.

### 11. 중요 지표 선별

지표를 많이 두면 아무것도 안 본다. 역할별로 몇 개만 고른다.

| 역할 | 개수 | 뜻 | 치과 예 |
|---|---|---|---|
| 의도 지표 | 1 | 진짜 의도(사업 성과) | 재방문율·소개 환자 수 |
| 북극성 지표 | 1 | 재정의한 목표의 결과 | 대기 관련 불만 건수 |
| 선행 지표 | 1~3 | 파레토로 고른 항목을 움직이면 바로 변하는 것 | 대기 안내 노출률, 대기 중 콘텐츠 시청률 |
| 가드레일 | 1 | 좋아지는 척 다른 걸 해치지 않는지 | 실제 대기 시간 |
| 허영 지표 | - | 보기 좋지만 쫓으면 안 되는 것 | 대기실 인테리어 만족도 |

**고르는 방법.** 강의에서는 고객 FGI로 고른다고 소개한다. FGI는 6~8명을 모아 진행자가 1~2시간 대화하게 하고 관찰하는 정성 조사다. 다만 목소리 큰 사람에게 쏠리기 쉽고, 말과 실제 행동이 다를 수 있어 보통 다른 방법과 섞는다.

| 코드 | 방법 | 골라 주는 것 |
|---|---|---|
| `fgi` | 포커스 그룹 인터뷰 | 집단 반응, 공통 언어 |
| `interview` | 1:1 심층·JTBD 인터뷰 | 고객이 '고용한 일', 핵심 고통 |
| `observation` | 현장 관찰·사용성 테스트 | 말이 아니라 행동에서 막히는 곳 |
| `voc` | 문의·리뷰·환불 사유 집계 | 불만이 실제로 몰리는 소수 원인 |
| `quant` | 퍼널·코호트·상관 분석 | 어느 단계·지표가 결과를 가장 움직이나 |
| `survey` | 카노·MaxDiff·컨조인트 | 후보 간 진짜 중요도 순위 |
| `experiment` | A/B·가짜 문·사전 예약 | 돈과 클릭으로 확인한 우선순위 |
| `scoring` | ICE·RICE·전문가 합의 | 빠른 1차 거르기 |

흔한 조합: 고객 목소리 데이터와 퍼널 분석으로 후보를 좁힌다 → FGI나 인터뷰로 '왜'를 확인한다 → 실험으로 최종 검증한다.

DB 핵심 사례 90건을 집계하면 정량 분석과 실험이 가장 많고, FGI로 확인된 사례는 없다. 실제 성공 사례는 행동 데이터와 관찰에서 고른 경우가 많다는 뜻이다(대부분 '추정' 표시이니 경향으로만 본다).

## 5. 한 사례로 처음부터 끝까지: 타이트사주 '신뢰'

| 단계 | 내용 |
|---|---|
| 5 Why | 왜 환불·불만이 나오나? 결과를 못 믿는다 → 왜 못 믿나? 명식이 틀렸다 → 왜 틀렸나? 만세력 계산(절기·시각)이 부정확했다 → 근본 원인: 계산 정확도 부족 |
| 문제 | 고객은 해석보다 내 명식이 맞는지를 먼저 보고, 틀리면 전부를 불신한다 |
| PEST (P·T) | 기술(범용 AI 만세력 오류로 정확도가 차별점이 됨), 법(청약철회가 환불 방식을 제약). 사회 요인은 참고 |
| 3C | 고객: 명식을 확인하는 고객 / 경쟁: 계산이 틀리는 범용 AI 사주 / 자사: 전문가 협업 → 빈자리: 계산이 정확한 사주 |
| SWOT | SO: 전문가 협업(강점)으로 '정확도가 차별점'이 된 기회를 잡아 계산 정확도를 앞세움. WO: 초기 오류 평판(약점)을 명식 공개·수정 경로로 메움. ST: 오류 평판 확산(위협)을 전문가 협업으로 정확도를 공개 검증해 막음 |
| 가설 | 해석 문장을 더 길게 / 결과 첫 화면에 명식을 먼저 보여 준다 / 천문 데이터로 계산 보정 / 환불을 어렵게 |
| 의심 | 해석을 늘리는 것은 '뻔함'. 환불을 막는 것은 '불가능'(규제). 명식을 먼저 보여 주는 것은 '통념의 맹점'(고객은 명식을 모른다는 통념) |
| 관습 파괴 (과정) | 그 통념이 확인 단계를 없앴다 → 아는 고객이 먼저 틀린 곳을 찾고 전부를 불신한다 → 계산을 보정하고 명식을 먼저 보여야 한다 |
| So what (결론) | 해석보다 계산을 먼저 맞춰라 |
| 안티오피니언 | "만세력이 처음부터 틀리고 일간부터 다르다"(Blind) |
| 트레이드온 | 빠른 출시 대 계산 정확도 → 출시 후 전문가·천문 데이터로 보정해 따라잡았다 |
| 목표 재분석 | 해석 문장 개선 → 계산(명식) 정확도 확보 |
| 이슈트리 | 해석 문장 / **계산 정확도 ← 공략** / 환불 |
| 파레토 | 만세력 보정(큰 베팅), 환불 경로 노출(퀵윈) |
| 대체 왜 | 계산을 왜 고치나? 믿게 된다 → 믿음이 왜 중요한가? 환불이 줄고 재구매가 생긴다 → 진짜 의도: 환불 감소와 재구매 매출 |
| 중요 지표 | 의도: 환불률·재구매율 / 선행: 계산 오류 불만 비중, 명식 수정 요청률 / 가드레일: 입력 완료율 / 허영: 해석 문장 길이 |
| 해결 | 전문가 협업·천문 데이터로 만세력 보정, 이후 재구매율 약 35%(회사 발표) |

전체 사례의 체인은 [so-what.md](so-what.md)에서 같은 순서로 읽을 수 있다.

## 6. 자주 하는 실수

- **증상에서 바로 해결로 간다.** 5 Why로 근본 원인까지 내려간 뒤 문제를 정의한다.
- **과정만 길고 결론이 없다.** 관습 파괴 과정 끝에 So what 결론을 한 문장으로 내린다.
- **환경을 안 본다.** PEST로 "왜 지금 되는가"를 확인하되 P·T 위주로 본다.
- **SWOT 4칸을 다 채운다.** SO·WO·ST만 쓰고 WT는 뺀다.
- **경쟁을 같은 업종으로만 본다.** 3C의 경쟁 칸에는 고객이 대신 쓰는 것까지 넣는다.
- **가설을 적자마자 평가한다.** 가설설정 단계에서는 판단을 미룬다.
- **클라이언트의 가설을 그대로 받는다.** 첫 가설일수록 의심한다.
- **안티오피니언을 지어낸다.** 실제 목소리가 없으면 '추정'이라고 밝힌다.
- **트레이드오프를 당연하게 받아들인다.** "둘 다 잡으려면?"을 한 번은 묻는다.
- **이슈트리 갈래가 겹친다.** 갈래끼리 겹치지 않는지, 빠진 갈래는 없는지 본다.
- **모든 하위 이슈를 다 하려 한다.** 속도×임팩트로 소수만 고른다.
- **말한 목적을 진짜 목적으로 믿는다.** '대체 왜'로 사업 의도까지 올라간다.
- **모든 의도를 올려야 한다고 본다.** 매출은 지키기만 해도 되는 경우가 많다. 올리기인지 지키기인지 먼저 정한다.
- **지표를 많이 둔다.** 의도·북극성·선행·가드레일만 남기고, 허영 지표는 명시해 버린다.
- **FGI 하나로 결정한다.** 데이터와 실험으로 교차 확인한다.

## 8. 아이디어가 먼저 나왔을 때: 역으로 근거 만들기

현장에서는 문제 분석보다 아이디어가 먼저 나오는 일이 많다. 이때는 반대 방향으로 간다: **아이디어 → 그것이 맞으려면 사실이어야 할 전제 → 전제별 근거 → 설득.** 근거를 모으다 전제가 깨지면 숨기지 않고 아이디어를 고치거나, 정방향(5 Why부터)으로 돌아간다.

| 방법 | 보여 주는 것 | 핵심 |
|---|---|---|
| 설문조사 설계 | 고객이 무엇을 중요하게 여기나 | 우리 안의 장단점을 먼저 알고, 장점이 비교되는 항목은 늘리고 단점이 두드러지는 항목은 줄인다. 예: 어디서나 작동하지만 반응이 느린 센서는 '반응 속도' 항목을 최소화, 빠르지만 반사 표면에서 안 되는 센서는 '반응 속도' 항목을 최대화 |
| 수치 대입 | 시장과 우리 사업이 어디로 가나 | "제가 좋아해서 잘 압니다, 급성장 중입니다"를 숫자로 바꾼다: 대안 시장(배드민턴·탁구)의 저성장 수치, 본체 사업의 하락 추세 수치, 개인 주장이 아닌 현 시점의 트렌드 |
| 컨슈머 저니 | 고객이 언제, 어디서, 왜 우리를 만나나 | 구체적인 한 사람의 하루를 이야기로 쓴다(예: 졸업을 앞둔 21세 김유리, 아침 인스타그램 광고로 우리를 만나고, 방학에 토익 점수가 꼭 필요하다). 하루 동선(집 과천 → 버스 → 강남역 플랫폼 → 귀가) 위에 장면 3~5개를 고르고, 장면마다 시간·장소, 상황·감정, 접점, 메시지, 다음 행동을 적는다. 접점은 쌓인다(인스타그램·유튜브 → 버스 → 지하철 플랫폼 광고 → 웹사이트 방문). 메시지는 그 장면의 불편을 말해야 한다("학원을 왕복할 시간에 토익까지") |

**주의.** 항목 비중은 우리 강점에 맞춰 고를 수 있지만, 한 문항 안에서 답을 유도하면 결과가 거짓이 된다. 우리 쪽으로 고른 설문은 "우리 강점이 고객에게 의미가 있다"는 증거이지 "고객이 우리 안을 원한다"는 증거가 아니다. 보고서에는 무엇을 덜 물었는지 함께 적는다. 숫자도 유리한 기간만 잘라 쓰지 않고, 출처와 시점을 적는다.

## 9. HOW: 솔루션을 제안할 때의 다섯 원칙

솔루션 제시에도 원칙이 필요하다. 예시는 "매년 줄어드는 볼펜 매출 → 신사업" 의뢰다.

| 원칙 | 한 줄 | 볼펜 회사에서 |
|---|---|---|
| 믿지 마라 | 클라이언트가 말하는 문제를 믿지 마라. 클라이언트나 나 자신의 첫 판단은 틀려 있을 가능성이 더 높다 | 매출 감소는 사실, "디지털로 전환하자"는 검증할 해석 |
| 누수 확인 | 누수가 없는지 끝까지 확인하라(갈래·숫자·논리·실행·이해관계자) | 잉크 인증·병원 판로·생산 비용 중 비어 있는 곳 |
| 해답의 수 | 문제를 해결하는 답은 절대 하나가 될 수 없다. 위대한 기획자는 모든 것을 한 번에 해결하는 단일 솔루션을 제안하지 않고, 솔루션의 한계를 인정한다(어깨 부상도 물리치료+수술+약처방) | 의료용·바디페인팅 두 갈래와 각각의 한계 |
| 자기부정 | 길을 잘못 들면 곧바로 U턴하라. 어디가 잘못됐는지 찾아 그 지점까지만 역산하고, 파트마다 그렇게 해 갈아엎는 양을 최소화한다. 브레이크와 메이크의 반복 | 전자펜(해결) → 아날로그는 디지털과 반비례하지 않음(본질)·애플·삼성을 이길 비용·인력 없음(현실) → 가설 단계로 U턴, 볼펜의 속성(인체 무해·잘 지워짐)을 새 시장에 |
| 후속 액션 | 솔루션 제시 이후 한 단계가 더 남았다: PHASE와 책임자 지정 | PHASE 01 시장개척(의료용 펜) → PHASE 02 신제품개발(바디페인팅 펜) → PHASE 03 다각화는 오늘 과감히 제안하지 않음. 네이밍·메시지는 우리가 O월 O일까지, 컬러 잉크는 A님, 의료시장 분석은 마케팅팀 B님과 함께 |

## 10. (2장) 인사이트 도출 방법

기획의 재료는 인사이트다. 인사이트는 누구나 찾는 정보가 아니라, 그 밑의 "왜"를 꿰뚫어 본 남들이 못 본 본질이다. 예시 상황: 다음 주부터 캠핑 브랜드 기획을 맡는데 캠핑 경험·지식이 전혀 없고, 일주일 안에 깊은 인사이트를 뽑아야 한다.

| 묶음 | 방법 | 핵심 |
|---|---|---|
| BASIC (하나의 세트) | 직접 경험 | 제한된 시간 내 최대한 많이, 다양하게 — 장비 고르기부터 보관까지 전체 |
| | 박식한 지인과 많은 대화 | 경험에서 생긴 질문을 들고 가 사실 → 경험 → 왜 → 해석 순으로 |
| | 온·오프라인 자료 | 사용자가 쓴 글 → 현장(매장·박람회) → 정리된 자료 순. 반복·의외·돈을 표시 |
| 상위 1% | 그 주제의 작품을 본다 | 만화·애니메이션·영화·드라마·소설 — 사람들이 동경하는 것(감정 인사이트). 반드시 현실로 확인 |
| | 생계를 잇는 사람 인터뷰 | 좋아하는 사람이 아니라 그 일로 먹고사는 사람 — 고객 패턴과 돈의 흐름 |
| | 효과적인 인터뷰 대상+ | 전문 기자·잡지 에디터 — 업계 전체와 본질. 읽고, 가설을 들고 간다 |
| 검색 | 기획자의 인터넷 검색 | 인터넷에 모든 것이 있지만 모든 인사이트가 있지는 않다. 구글 100페이지 이상까지 파면 본질이 보인다. 검색과 인터뷰를 오간다 |

**1차 정보와 2차 정보.** 1차 정보는 직접 보고·듣고·잰 원래 자료, 2차 정보는 누군가 해석·요약·전달한 것이다. 2차 정보를 최대한 외면하는 것이 기획자의 핵심 자세다 — 특히 결정할 때. 외면은 듣지 말라는 게 아니라 결정의 근거로 삼지 말라는 뜻이고, 2차 정보는 무엇을 확인할지 알려 주는 단서로 쓴다.
- 싱가폴 지사 보고("SUV가 대유행이니 라인업을 대폭 늘려야 한다")를 그대로 상부에 올리지 않고, 최근 5년간 브랜드별 판매율·SUV 판매 추세를 직접 확인·분석한 뒤 우리가 직접 의견을 낸다. 보는 사람에 따라 상황 파악은 놀라울 만큼 달라진다.
- 원료 단가: 영업 담당의 전언("낮춰주지 않으면 업체를 바꿀 수도 있다")과 고객사의 직접 발언("품질은 귀사와 큰 차이, 바꿀 생각은 없다, 단가는 고려해 봐 달라")은 결정을 정반대로 만든다.
- 습관: 출처를 거슬러 올라가고, 원본·당사자를 직접 보고, 정보에 등급(1차 직접·1차 당사자·2차 전언·2차 해석)을 붙이고, 결정에는 1차만 쓴다.

인사이트 점검 여섯 질문: 의외인가, 여러 현상을 설명하나, 경험·사람·자료 중 둘 이상에서 확인됐나, 1차 정보로 확인됐나, 행동으로 이어지나, 남들이 아직 안 하나(1장 Why not yet).
