# planning

기획 공부·아이데이션 툴의 **사례 DB**입니다. 지금은 DB만 있고, 툴 화면은 보류 중입니다.

방법론: **WHAT**(무슨 문제를 풀 것인가) → **가설**(최대한 많이) → **Why not yet**(왜 지금까지 아무도 안 했나?) → 해결

Why not yet은 두 가지 일을 합니다.
1. 뻔하거나 불가능한 아이디어를 제거한다 → `obvious`(뻔함), `impossible`(불가능): 탈락
2. 주목하지 않던 아이디어가 빛나는 아이디어였음을 깨닫게 한다 → `blindspot`(통념의 맹점), `timing`(타이밍): 생존

|---|---|

## 사례 형식
```jsonc
{
  "id": "dental",
  "kind": "real",            // real: 실제 사례 재구성 · practice: 연습용 가상 사례
  "domain": "의료·서비스",
  "title": "치과 대기 경험",
  "source": "출처 설명",
  "verified": true,          // refs(출처 링크)가 있으면 true
  "refs": ["https://…"],
  "what": {
    "situation": "상황",
    "symptom": "겉으로 보이는 현상",
    "problem": "다시 정의한 문제 (Problem is ___)"
  },
  "hyps": [
    { "text": "가설", "perspective": "customer", "why_not_yet": "왜 아직 안 했나", "verdict": "blindspot", "reason": "판정 이유" }
  ],
  "solution": "해결 (Solution is ___)",
  "lesson": "이 사례에서 배울 점"
}
```
- `perspective`: customer(고객) · timing(시점) · price(가격) · channel(채널) · competitor(경쟁) · constraint(제약) · belief(통념)
- 사례마다 생존 가설과 탈락 가설이 각각 하나 이상 있습니다.

## 사례 목록
실제 사례 중 ✓는 출처 링크를 확인한 것입니다. ✓가 없는 실제 사례는 일반적으로 알려진 내용을 바탕으로 해서, 인용하기 전에 확인이 필요합니다.

| id | 제목 | 구분 | WHAT: 현상 → 문제 |
|---|---|---|---|
| `dental` | 치과 대기 경험 | 실제 | 대기실 불만이 많다 → 환자들이 기다리는 시간을 지루하고 불안하게 느낀다 (공간의 질이 아니라 시간의 질) |
| `elevator` | 느린 엘리베이터 | 실제 ✓ | 엘리베이터가 느리다는 불만 → 사람들은 기다리는 시간 자체가 짜증 나고 지루하다 |
| `baggage` | 공항 수하물 대기 불만 | 실제 ✓ | 수하물 대기 불만 → 승객은 전체 시간보다 '멍하니 서서 기다리는 시간'을 길게 느낀다 |
| `disney` | 놀이공원 긴 줄 | 실제 ✓ | 대기 줄이 길다 → 손님은 할 일 없이 끝이 안 보이는 줄에서 기다리는 걸 힘들어한다 |

| `dyson` | 청소기 흡입력 저하 | 실제 ✓ | 흡입력이 떨어진다 → 먼지봉투의 미세한 구멍이 막히면서 흡입력이 떨어지는 구조다 |

| `milkshake` | 밀크셰이크 매출 늘리기 | 실제 ✓ | 밀크셰이크 매출 정체 → 아침 고객은 '길고 지루한 운전을 버티며 배를 채울 것'을 사러 온다 |

| `ikea` | 가구가 비싸고 운반이 어렵다 | 실제 | 가구가 비싸다 → 가격의 상당 부분이 조립된 부피를 보관·운송하는 비용이다 |

| `baemin` | 배달 음식 주문의 불편 | 실제 | 전단지를 찾기 어렵다 → 동네 가게 정보가 흩어져 있어 비교하고 고르기 어렵다 |

실제 사례는 모두 학습용으로 단순화한 재구성입니다. 공항 수하물 사례는 널리 인용되지만 공항·연도가 확인되지 않았다는 지적이 있어 '전해지는 이야기'로 다룹니다.
